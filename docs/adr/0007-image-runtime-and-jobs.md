# Single-image runtime and durable local jobs

Implemented for the single-image Linux preview, 2026-09-07. This supersedes the placeholder worker design; actual validation and remaining boundaries are recorded in ../image-validation.md.

The application remains a modular C++20 system with a React/TypeScript client, Drogon HTTP adapter and an independent CLI. Both entry points call the same image engine. SQLite owns job state and a sequence-numbered event journal. An isolated worker owns Vulkan and model memory. The HTTP process supervises one worker at a time and continues serving uploads, progress, history and cancellation while inference runs.

The first executable profile is `seedvr2-3b-image-fp32-b-v1`: one image, official 3B weights, positive text conditioning, timestep 1000, one Euler endpoint evaluation, CFG 1, stochastic VAE posterior, latent scale 0.9152, no color correction. Each of the 32 DiT blocks is loaded, executed and released in order. The VAE, patch projections and all attention operations execute through the selected ncnn backend. Host-side image layout, random sampling and Euler arithmetic are reported separately. Backend fallback is forbidden.

A model package is an immutable manifest plus relative, SHA-256-addressed files. Package availability, complete execution, FP32 numerical agreement, visual quality and model certification are separate states. Importing correct weights does not issue a certificate. FP32-B is an explicit reference adaptation; it does not establish parity with official BF16/FlashAttention execution. Fixed conditioning is baked by the exporter with source and tensor hashes; runtime never needs Python.

Public engine contracts use standard C++ value types and progress callbacks. ncnn tensors, SQLite handles and HTTP types remain inside their adapters. The worker emits versioned newline-delimited JSON; the supervisor persists events before exposing them. Jobs transition through queued, running, cancelling and terminal succeeded/failed/cancelled/interrupted states. Restart recovers unfinished jobs as interrupted, retaining inputs and diagnostics; retries are new jobs. A result becomes visible only after successful PNG and report finalization. Cancellation cannot publish a partial result.

The default interface is upload, choose output size/device, run, compare, download. Advanced options and execution evidence live behind expandable controls. Result records preserve input/output hashes, package identity, seed/noise algorithm, processing dimensions, backend, per-stage timing and errors. Browser requests refer to workspace IDs, never arbitrary host paths. CLI users may explicitly select local input, output and package paths.

Initial numerical validation uses the unchanged official NaDiT forward method, patch methods, AdaSingle and all 32 original blocks with bounded lazy weight loading. It preserves the shared cache: the official output AdaSingle reads the first attention embedding from the cache populated by block zero. Reference noise tensors are shared exactly with the native execution so random-number differences do not mask arithmetic errors. Tests cover failure and cancellation, package tampering, restart recovery, and actual complete-image outputs. Temporal VAE, video processing, reduced precision and higher-resolution optimization follow separate measured milestones.

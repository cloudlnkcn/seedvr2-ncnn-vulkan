# ADR 0008：整段短片与独立媒体适配

日期：2026-09-07。状态：已实施为 0.5.0 实验性预览；数值验收为 MIXED。

## 问题

单图引擎的 VAE 是 T=1 特化，不能把逐帧调用当成 SeedVR2 视频移植。用户需要同一款便于测试的本地 Web 与独立 CLI，且工程测试与模型认证必须分别记录。

## 决定

1. 共用完整 DiT 图、AWA、包校验和图调度，分别由 image/video orchestrator 组织实际媒体张量。视频使用完整 3D VAE 权重和时间相位。
2. 新增 `seedvr2-3b-video-fp32-b-v1` 模型身份及 VideoJob 请求，服务器在入队前校验请求和媒体类型。实际执行前重新核对包内文件。模型清单存在不代表已认证。
3. 首个实现只处理 1–17 帧、64–128 长边的整段短片，memory disabled；尾帧补到 4n+1，解码后裁回实际数量。后续缓存与 chunk 需要另行定义数值契约，不能沿用本次通过结论。
4. 四类时序 VAE 自定义模块经过 pnnx 显式边界导出和 lowering；C++/Vulkan gather/scatter 与 ncnn 原有 Convolution/SDPA 组合执行。时间卷积保持原始核，不静默退到 CPU。
5. FFmpeg 共享库承担本地容器、视频编解码和时间戳，C++ 核心不依赖 Python/Node 或外部命令。当前输出 libx264 MP4，无音轨，只支持明确的 8 位 SDR 范围。
6. 复用进程监督与 SQLite schema 3。视频按整段原子结果提交；取消/崩溃不会提供可下载的半成品。HTTP byte ranges 支持浏览器定位，Web 增加同步播放及暂停同帧。
7. 保留 17 帧完整轨迹失败；用户可以在明确标记的预览范围内做功能测试，正式模型证书保持未签发。每份数值报告绑定输入、噪声、模型包、实际运行和构建。

## 代价与后续

时序 gather 有额外 scratch 开销，FP32 权重加载仍占显著成本，本版没有高分辨率或实测峰值内存保证。系统 FFmpeg/libx264 增加 ABI 与完整应用许可的发行工作；目前只完成本机开发安装。

6 帧 64×64 为 73/73 PASS，17 帧 128×128 Vulkan 为 60/73、CPU 为 70/73，后者均为整体 FAIL。下一步先隔离后段 DiT 差异，再建立真实视频质量集、缓存/分块一致性与可测内存策略。详细证据见 [视频验证](../video-validation.md)，媒体和导出契约见 [视频运行时](../video-runtime.md)。

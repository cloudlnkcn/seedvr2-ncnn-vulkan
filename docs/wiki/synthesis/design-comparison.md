# 设计对照与冲突核对

结论基于 2026-09-13 登记的源码与说明，属于设计审阅，不是统一设备上的竞速测试。出处见 [同类实体](../entities/peer-ports.md) 和 [来源登记](../sources.json)。

| 维度 | 本项目设计 | 对照得到的行动 |
| --- | --- | --- |
| 应用边界 | CLI / Web worker / 安装 SDK 共用原生执行；任务与模型分开 | 保留现有职责拆分。公开文件型 API 的边界，等实际接入需求再扩展内存帧输入 |
| 可直接使用 | 已有源码构建、官方 checkpoint 下载和本机转换包 | 借鉴 zimage 的程序发布、同类项目的转换包托管；先完成清晰的安装和包校验 |
| 原生数值 | 固定 FP32-B 参考、73 边界完整性检查、保留失败 | 补官方默认 BF16 参考后再讨论新的低精度路径 |
| 视频计算 | 整段时序 VAE + 三维 AWA，范围很小 | 可参考 Chisato 的 VAE query 分块和时间状态，分别做组件验证 |
| GPU / 内存 | 逐图装载释放，权重自动放置，图间传输 | 测量 load、upload、compute、download 后决定融合/驻留，不先假定瓶颈 |

## 本轮关闭的认识偏差

1. **“官方同类”含义。** Discussion 位于 Tencent/ncnn；具体项目由各作者维护，不能把帖子作为官方全模型认证。
2. **“支持视频”不是同一个范围。** `aichi-port` 当前 README 写的是独立帧目录；`chisato-port` 的 VAE 源码有真正的时间状态。高分辨率图片的展示也不能直接当成长视频验收。
3. **图合并的预估被后续测量修正。** `aichi-port` 固定版本 README 的性能部分说明，旧的传输占比估计受到权重加载和页缓存混淆；该作者当前报告 chunk 1→2 的 DiT 端到端收益约 0.9%，扣除加载后的图结构收益约 1.8%，chunk 4 无进一步收益。这是对方输入/设备上的报告，本项目不能直接套用。
4. **更大的 PSNR 不自动代表更好的修复。** 相对 PyTorch 的数值保真与相对固定目标的任务质量，需要分别展示。

保留逐图架构是当前可诊断、可释放权重的合理起点；是否合图由后续计时决定。现有应用层已经够用，优先补模型获取、官方参考、VAE 边界和真实质量证据。

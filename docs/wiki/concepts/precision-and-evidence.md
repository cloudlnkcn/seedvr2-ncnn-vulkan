# 数值、画质和包身份

比较依据来自 `numerics-v2`、`aichi-port`、`ernie-evidence`，精确来源见 [登记](../sources.json)。

| 问题 | 需要的证据 | 不能由它推出 |
| --- | --- | --- |
| 这是哪个模型包？文件完整吗？ | 审阅过的 payload 身份、文件清单、大小、SHA-256 | 数值正确、官方签名、画质通过 |
| 能完整执行吗？ | 固定输入、参数、程序和设备的成功报告 | 与官方张量一致 |
| 数值接近谁？ | 参考实现及精度、完整张量边界、误差协议、同一噪声输入 | 对真实任务必然有效 |
| 修复画质如何？ | 固定目标、退化过程、bicubic 等基线和时序协议 | 所有输入或设备都有效 |
| 是否更快、更省内存？ | 同输入/设备/精度、冷暖文件缓存、分项计时与峰值 | 另一台 GPU 会有相同收益 |

本项目六条 FP32-B 轨迹的 73/73 是固定数值协议结果，原始失败保留在 [数值修复说明](../../NUMERICS-REPAIR.md)。官方默认 CUDA BF16/Apex/FlashAttention 是另一条参考路径，尚不能从 FP32-B 的通过结果推定通过。后续必须把权重存储、激活存储、运算/累加精度分开记录。

同类 SeedVR2 的 README 给出了相对 PyTorch 输出的 PSNR；本项目画质表中的目标是保留源视频的固定目标。两个 PSNR 的被比较对象不同，不能直接用分贝数排名。`aichi-port` 还明确区分了文件名所写的计算精度与实际权重存储格式，因此下载包不能仅由名称判断精度。

`ernie-evidence` 的参考分层说明值得借鉴：先说明官方路径，再建立 FP32 桥接，再比较原生 CPU / Vulkan。但 ERNIE 的层数、图尺寸、误差阈值和硬件条件不进入本模型的验收协议。

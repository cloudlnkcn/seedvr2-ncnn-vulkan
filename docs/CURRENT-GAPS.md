# 当前还缺什么

2026-09-13。已有完整 SeedVR2 3B 原生图片和短视频流水线、共享 CLI/Web/SDK、固定参考回放、首次使用预检、自动官方权重下载、模型完整性检查和真实对照图。原始两个视频数值失败已在固定 FP32-B 范围内关闭，详见[修复记录](NUMERICS-REPAIR.md)。本轮按[来源与验证闭环](wiki/README.md)补充分发工具及设计对照，实际结果见[本轮记录](wiki/synthesis/delivery-2026-09-13.md)。

作为面向已有 C++、PyTorch、Vulkan 基础读者的移植教程和工程 Discussion，目前可以展示完整路径和可核验结果。若目标是普通用户直接下载使用的通用视频修复应用，还缺下面这些实际交付内容。

| 优先级 | 缺口 | 下一步的明确验收 |
| --- | --- | --- |
| 高 | 有代表性的修复画质和时序质量 | 固定多个来源、人物/文字/快速运动等场景，保留目标与基线；预先定义协议，观察伪细节和连续帧稳定性。目前三段素材来自同一来源，原生与官方 FP32-B 均低于 bicubic |
| 高 | 新机器与跨发行版交付 | FP32-B / DiT FP16 模型库已公开，完成固定 revision 全量回读、原生包校验及安装执行；提供固定版本下载入口。仍缺干净目标机的下载/首次执行验证与通用程序发行。Fedora 安装依赖系统库，不是通用 Linux 二进制 |
| 高 | 转换成本的完整测量 | 记录从原始权重到 36 图包的峰值 RAM、磁盘临时空间和时间；约 14.57 GB 官方文件、约 20 GB 图包不等于峰值空间预算 |
| 中 | 更多设备的 FP32 数值证据 | Linux 单 NVIDIA 全模型已测；AMD/Intel 真机仍缺。llvmpipe 不满足当前 FMA 残差要求，应用已拒绝该完整数值路径，CI 按能力跳过相关测试 |
| 中 | Windows/macOS 原生交付 | 各平台原生构建、路径/安装/媒体/SDK 验证，然后单独做大模型实机。现有 Linux CI 不能代替这些结果 |
| 中 | 官方默认低精度路径 | 保存官方 CUDA BF16/Apex/FlashAttention 输出后，再设计各自的转换与误差协议。已有 DiT FP16 存储 + FP32 计算的五条完整轨迹与独立误差报告；这不等于官方默认 BF16 或原生低精度算术 |
| 按需求 | 更高分辨率、长视频、音轨与 HDR | 先确定资源和质量范围，再实现分块/时间 cache 等。当前图片长边 ≤512，视频 ≤17 帧、长边 ≤128，输出无音轨 SDR MP4 |
| 按测量 | 更细的内存和性能优化 | 区分权重、激活、工作区、文件缓存；做受控重复测量。当前逐图权重放置和 RSS/整卡显存采样已有，但没有激活卸载、OOM 自动重试或完整分项峰值 |

本模型没有自回归 KV cache。没有当前需求的插件框架、通用调度层、7B 移植和研究性精度优化，不作为本次 3B 数值修复交付的前置条件。

发布材料应同时链接通过记录、画质负结果和设备边界。项目分享已发布到 Tencent/ncnn 的 [Discussion #6991](https://github.com/Tencent/ncnn/discussions/6991)，仓库保留[发布正文](DISCUSSION-DRAFT.md)；仓库开源、CI 通过、模型包哈希通过和任务画质通过分别报告。
